# 原版 SDLC 兼容规则

本文件对应随 Skill 一起安装的 SDLC AI SPEC 包。实际调用时先只读核对同一包的
`UPSTREAM.json`、工作流和脚本；若目标项目安装了另一版本，也须核对其实际规则，
不能把这里记录的路径与行为当作未知版本的保证。

## 保持原版行为

CUT 是独立操作，不加入 120、320 或其他编号阶段。
不修改 STATUS、阶段映射、阶段调用条件、核心脚本、模板、loader、上游锁文件、安装与升级机制。
不要求原版解释 FROZEN、SPLIT、CLOSED 或父子状态，不维护父级完成回调。
不写业务项目 feature.json，不修改调用者环境。只读当前选择可用于解析来源。
不创建 hook、chmod 锁定或全局 AGENTS 规则来拦截来源需求。

## 项目与来源定位

先确认业务项目根目录，避免误用插件安装目录或其他项目。
优先使用用户明确来源目录。用户未明确时，只采用当前项目中唯一可解释的原生选择。
当前原版定位中 SDLC_FEATURE_DIRECTORY 优先于 feature.json 的 feature_directory；SDLC_FEATURE 只用作标签。
用户输入 002 时，如匹配多个目录，不依照修改时间或排序猜测。
后续交接提供完整目标目录，提醒旧目录参数可能仍指向来源。不能声称 CUT 已切换活动需求。

## 编号与后继身份

默认延续项目既有正常新编号。例如已有 001、002、003，拆分 002 后建议 004-a、005-b，保留原 002。
编号表示稳定标识，不表示业务优先级。候选编号在应用前检查占用；预览不预留编号。
用户明确选择 002-a、002-b 时，把它们作为普通需求目录，并全程使用完整路径。
当前编号扫描读取开头数字；两个后缀目录都使用 002 前缀。原版不会因此获得层级、进度汇总或回到 002 的语义。
项目已有时间戳规则时继续采用；未知自定义规则要求明确目标，不复制一套新的复杂编号器或扫描远程分支建规则。
冲突时调整具体方案，不能覆盖已有目录或静默改号后继续按旧确认发布。

## 来源保留

保持来源 spec、plan、tasks、证据及其他原文件字节不变。正式来源只新增一次性承接说明，名称与内容应用前固定。
同名说明已存在时选择明确不冲突路径，不覆盖原文件；记录该路径用于同次恢复。
“冻结”只表示保留来源、约定工作转到后继。原版 STATUS 仍可反映来源文件中的旧阶段和未完成任务。
用户显式向来源运行原版 IMPL 时，原版仍可能执行；CUT 不提供硬锁，不隐藏该限制。
后继全部完成后，不回填来源任务，不归并后继材料，不再运行一次父级 IMPL/CONV，不自动删除或归档来源。
后续整理历史遵守项目既有规则，独立于 CUT 完成。

## 根据材料成熟度交接

| 现状 | CUT 输出 | 后续处理 |
| --- | --- | --- |
| 只有原始需求、画像和会议资料 | 已确认的后继 brief，或候选方案 | 每份简报作为原版 SPEC 输入 |
| 已有 spec | 按范围重组的规格和适用来源材料 | 有影响范围的疑问先澄清，否则继续规划 |
| 已有 spec、plan | 重组适用方案、契约与研究 | 补齐受新边界影响的规划，再分解任务 |
| 已有 tasks、尚未实现 | 适用标准文档、任务与映射 | 确认新方案和任务仍成立；有缺口先修订，再按需要 XCHK/IMPL |
| 已部分实现 | 上述材料及实现承接、剩余工作 | 依据实际缺口选择规划、XCHK、IMPL 或 CONV |

任务完成拆解不是使用 CUT 的前置条件。文件存在也不证明某个阶段已通过。
不得建立空壳 plan/tasks 只为满足原版文件检查。
原始材料模式不先创建虚假的正式父需求；无合法 SDLC 初始化时不为存操作记录创建假的 .sdlc 标记。

## 避免重新生成造成损失

已有完整后继规格时，不无条件运行 SPEC。当前 SPEC 包含目标规格初始化行为，可能重建已经迁移的内容。
需要重新拆任务时才使用 TASK；不能承诺它保留 CUT 已迁移的任务编号、勾选和人工修改。
原需求有 tasks 不证明新范围的 plan 仍适用。先明确设计与发布策略缺口，再同步任务。
XCHK 可检查材料关系，但不能代替实际修订方案。CUT 不把 XCHK 设成所有拆分的固定门禁。
原 IMPL 有规划、任务和适用清单前置；保留这些条件，不删除未完成清单绕过提问。
原 CONV 按当前代码检查全部任务，包括已勾选任务，只追加差距任务；它不负责材料迁移，也不检查 Git 历史。
仅当前代码对新规格的覆盖不清楚且材料齐备时，按需建议 CONV；不要固定运行，以免重复登记已知未完成工作。
原流程是否通过、业务是否验收与能否发布，仍由原流程和项目既有规则决定。

## 标准材料与格式适配

读取本地项目实际规范、现有材料和必要的安装模板，不在 CUT 内复制一套原版完整 spec/plan/tasks 模板。
保持原版复选框和任务语法；部分实现与待核验写为普通说明和后续任务。
重要来源、共享基线、兄弟边界和发布限制写进后继适用的标准文档，不能只放在原版阶段不会读取的操作记录。
对不能可靠解析的自定义任务或检查清单保留原文，要求显式映射；不要用宽松正则声称识别完整。
本地版本与基准不同，先只读核对路径选择、产物与前置条件。未知格式先说明需要适配，不能通过改核心继续。
兼容适配限定在 CUT 自身，并保留用户不改原版的约束；无法证明兼容时，交付方案与明确缺口，不宣称可应用。
