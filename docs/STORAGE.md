# 工作区与权威资料库

## 契约与边界

这是本地存储、绑定和 INIT 的显式扩展。上游九阶段的业务顺序、条件、询问、
产物内容和完成含义保持不变；原始上游源码不变。公共入口仍为 11 项，不增加
`sdlc-sync`、`closeout` 或自动收尾。资料归拢不代表代码合并、任务验证或业务验收。

- main 指 Git 的主工作区，不是名为 main 的分支。非 Git 项目以选定项目自身为 main。
- 子项目按相对 Git 根的位置对应其他工作区，不把显式子项目提升为整个仓库。
- 权威库默认在 main 项目的 `.sdlc`。main 的 `.sdlc/store.json` 可以登记一个指定
  的绝对资料目录及外部候选来源；指定路径并不产生第二个权威库。
- 有本地独立 `.sdlc` 的 worktree 全程使用本地；没有本地的 worktree 正常读写
  权威库。有效库结构损坏、配置非法、实际选中的需求缺失时停止，不混用其他库补缺。
  独立本地库与权威库的规范路径不得相等或互相包含；合法且互不重叠的外部目录别名
  继续按原有规则处理，不能通过本地别名把普通写入导入权威库子树。
  写入前也检查需求目录内具体产物的规范目标；即使软链接目标尚不存在，也不能
  借该链接将本地产物写入权威库。合法且不触及权威库的外部产物别名仍可使用。
  隔离比较使用文件系统身份，大小写不同但指向同一对象的地址不能被当作独立副本。
  尚不存在的目标以最近存在的祖先及该目录的大小写、Unicode 规范等价查找规则判断；
  常规地址比较只读取现有条目元数据，不在用户目录中创建探针；写入归属检查采用下文的
  严格规则，无法证明有歧义的缺失地址与保留目标分离时停止。此检查不改写显式路径拼写、
  需求标签或选择持久化的 no-op 语义。
- main 登记异常不阻塞有效独立本地库的普通操作。此时 `AUTHORITY_DIR` 和
  `authority_exists` 为 null，`authority_error` 说明原因；不猜测权威位置。
  导入权威资料、无法核实的外部需求路径或本地目录别名仍然停止。
- 只有从 main 发起的归拢可以将副本资料纳入权威库。worktree 可以从权威库导入
  本地，但不能把本地副本回灌。普通共享写入不属于归拢。
- 当前代码项目始终用于实施、构建、测试和代码路径解释。`.sdlc/...` 资料路径
  映射到有效资料库；代码项目下的绝对 `.sdlc/...` 地址（含项目目录别名）也使用
  相同落点。`nested/../.sdlc/...` 和指回当前项目的目录别名也按同一身份映射，
  保存选择后重读不改变目标。不能为查找资料切换代码工作区。

这些是受支持入口的操作约束，不是操作系统权限隔离。任意外部文件编辑器不受
插件锁控制；发现并发变更应停止并重新准备，不能宣称能阻止所有外部写入。

## 程序与模型分工

程序负责发现、路径校验、操作资格、范围、快照、差异、过期检查、写入与恢复。
模型负责理解输入、呈现可选动作及来源、给出语义合并候选。用户已经明确指定的
方式和范围不重复询问；原则冲突、需求身份歧义和缺少证据的完成状态由用户裁定。
模型不通过复制整个目录、切换目录或直接编辑权威文件绕过归拢流程。

## INIT 决策

先只读发现，再明确选择动作；发现本身没有写入。

| 情况 | 动作 |
| --- | --- |
| main 无库且无来源 | 在权威位置初始化 |
| main 无库但有候选来源 | 选择归拢建立权威库或空白初始化 |
| main 已有库 | 保留补缺；归拢须明确选择 |
| worktree 已有本地库 | 保留补缺；导入权威资料须明确选择 |
| worktree 无本地、权威库存在 | 告知路径，选择共享或新建本地；建议共享 |
| worktree 与 main 都无库 | 选择建立空白权威库并共享，或初始化本地；其他副本由 main 归拢 |

新建本地默认导入宪法及项目长期记忆，可选具体需求，也可选择空白。首次导入在
模板补缺之前进行，不先生成宪法再覆盖。重复 INIT 不重写文档、不补造历史 provenance。
首次本地初始化显式指定需求时，必须先有可访问的权威来源且包含全部选定需求；
来源缺失时在创建本地库之前停止，不能将该请求静默转为空白初始化。
项目长期记忆约定为 `memory/long-term.md`，只保存项目共享事实、约束、决策及来源；
没有该文件时不创造内容，不复制个人记忆、聊天记录或整个 memory 目录。
所有阶段按需读取该文件作为项目上下文，它不替代宪法或用户指令。
首次本地导入先保存待完成的选择与来源字节，再禁止覆盖地原子发布带意图的本地目录；
目录可见前中断不会留下被误认作已有库的空目录，可见后中断使用原选择再次 INIT 补缺，
保留已存在文件。未完成库不能用于普通阶段或作为导入/归拢来源，恢复规则见
[INITIALIZATION.md](INITIALIZATION.md)。
首次导入、重复补缺和中断续跑均在预览与持锁发布前检查实际待创建目录、待写文件的
归属，不能借控制文件别名或权威外置产物别名写入保留目标。已有且不写入的文件
不增加归属依赖；可选宪法 provenance 单独失败仍只报告警告并保留已创建宪法。

## 当前需求与登记

保留原有 `feature_directory` 字段。本地库和 main 使用 `feature.json`；无本地库的
共享 worktree 使用有效库的 `workspaces/<项目绝对路径摘要>/feature.json`。
不读取其他工作区的选择，也不在导入/归拢时复制它。移动工作区后显式重新选择需求。
代码项目身份使用文件系统返回的真实目录拼写；大小写或 Unicode 等价的项目地址使用
同一工作区选择和 INIT 中断记录。显式需求路径仍按原始字符串处理，不因项目身份归一而改写。
STATUS 和路径查询始终只读，不创建选择、登记、锁或缓存。
STATUS 同样拒绝本地库与权威库重叠，不把权威资料误报为独立本地资料。
当前选择文件及有效库以内的父目录不能通过软链接共用 main 或其他工作区的选择。
读取和持久化均校验地址，持锁后发布前再次检查；地址检查不解析未使用的旧选择内容。
INIT 校验当前工作区的 `FEATURE_JSON`，共享模式不读取 main 的需求选择。
显式需求输入优先于已保存的选择；只有实际依赖已保存的选择时才要求该记录有效。
解析资料库地址、新建需求及按明确目标编辑文件不解析未使用的旧选择内容，仍保持
资料结构、目标权限与选择文件快照检查。显式选择是否持久化仍由原流程及
`SDLC_FEATURE_NO_PERSIST` 决定；只读查询不修复旧选择。
显式 `.`、`./` 指向代码项目根，保留原有路径呈现、需求标签及外部需求路径限制。
`.sdlc` 地址替换同样保留前导点、末尾 `/.` 和斜线；规范路径只用于边界检查，
不能改变原流程据路径拼写计算的需求标签或已保存的路径后缀。
保存选择时只按原流程移除当前项目的字面前缀，不把其他绝对别名一律相对化。
相同选择继续保持文件字节与修改时间不变；路径身份相同不构成额外写入理由。
导入/归拢的来源结构校验不依赖来源工作区的选择。

`store.json` 使用独立 `schema: 1`，记录 `authority` 和 `sources`，路径均为绝对路径。
该文件只在显式登记时创建。权威目标可以尚不存在；已经存在时必须是目录，普通文件在写入登记前拒绝。
已有权威资料不能因重新登记而被静默搬迁；更换已登记
权威路径属于另行迁移。普通旧项目继续使用原有布局与配置，不批量回写。

## 导入、归拢与普通资料写入

三种操作共用程序控制的候选写入流程：`import` 为权威到本地，`collect` 为 main
吸纳副本，`edit` 为当前有效库的普通业务写入。来源只能来自同仓库同子项目的
工作区或 main 显式登记的路径；发现不等于自动纳入。
`import` 只刷新已经存在的独立本地库；首次本地导入使用 INIT 的 `--mode local`。
没有本地库时，准备导入在创建目录或事务前停止，保持原有共享绑定和当前需求选择。
自动来源须核实当前 Git common directory、linked worktree 的登记回指以及对应
子项目仍属于该工作区。陈旧地址、被另一仓库接管或回指失配的地址不会作为自动
来源；应用时再次核实。显式登记的外部来源仍按登记处理。
Git 根、common directory、登记回指及来源目录按文件系统身份核对；大小写或 Unicode
等价的登记地址不会漏掉合法副本。重复的等价来源只准备一次；该处理不放宽仓库归属、
回指或 main 独占归拢的约束，也不改写显式需求字符串。

普通 `edit` 的快照与过期检查只包含明确的目标文件、`init-options.json` 及当前
工作区的 `FEATURE_JSON`，不扫描其他需求或其他工作区的选择。不同目标的候选可
依次应用；同一目标、本工作区选择或必要配置变化仍须重新准备。main 登记的损坏
或恢复不使独立本地编辑失效，程序仍重新检查当前项目与目标路径绑定。
`import`/`collect` 保留完整来源和目标快照及恢复流程。
完整快照遇到目录无法枚举或 I/O 错误时停止，不将未读取的子树视为空数据；来源快照
失败不能产生成功导入、无变化或模板回退的结果。已选择的来源在快照开始时缺失，
或在读取中消失、被替换时也停止；只有首次准备的目标库可以尚不存在，真实空来源仍是合法快照。
恢复仍使用已保存快照，不重新读取来源内容。
导入和归拢按目标文件系统查找规则绑定文件及父目录，保留已有名称。不同来源的等价名称
落到同一目标时形成一个候选：相同内容跳过，不同内容保留为待解决冲突。事务清单的
`copy_targets` 记录来源相对名称到实际目标名称的映射，应用与恢复使用同一份旧值；
不能因字符串键不同把原有文件当作新建文件删除。单个来源内多个文件折叠到同一目标，
或文件与目录的落点冲突时，在发布前停止。未知的 Unicode 查找规则仍不猜测。
控制文件权限仍按明确请求的逻辑地址校验，不因目标父目录的等价拼写改变权限。
缺少映射的旧事务继续支持无歧义路径；存在等价名称歧义时保留事务及现存数据，停止并
要求检查、重新准备，不能自动清除残留事务或把它标记为恢复成功。
普通编辑允许合法产物软链接，记录逻辑地址、实际目标及链接绑定，以实际目标
快照和发布并保留链接；应用和恢复时绑定必须仍然相同。不得借别名写入权威库、
插件、登记/事务文件或其他工作区的选择，也不能让多个目标别名形成重复写入。
普通读写中的宪法与长期记忆使用同样的真实目标校验，允许不越界的知识文件别名。
控制文件保护覆盖当前库、其他工作区和登记来源，包括尚未建立本地库的工作区；
不能因真实目标位于当前库之外而跳过检查。普通外部文档仅与控制文件同名时不受限制。
控制文件自身的别名也按真实地址识别；这些检查不读取其他工作区的选择内容，
也不将其内容或修改时间加入普通编辑快照。
业务产物自身没有软链接时，也检查它是否被控制文件别名引用；准备、应用和恢复
均重新核实该目标身份，普通编辑、导入和归拢共用此检查；恢复不重新依赖来源在线。
目标归属与普通需求路径选择分别比较。归属判断中，两个查询的 inode 不同不证明
潜在等价路径互不重叠；缺失目标也不能通过独立条目的 ENOENT 或 inode 变化排除。
明确不同的名称、相同已知祖先下相同的后缀及原生目录规则可提供依据；仍有歧义、
原生规则不可用或缺少所需 Unicode 规则时停止，不能使用目录条目探测授权写入。
这项规则用于控制目录、权威库外置产物和插件等写入边界，不改变普通需求地址的
解析、显式选择优先级或同选择 no-op。
普通编辑的重复目标检查也使用该归属规则；不同 inode 不能使潜在别名跳过比较。
准备、应用和恢复均重新检查明确的编辑目标，重复目标在首次发布前停止。
旧事务若含有歧义重复目标，保留当前文件和记录供检查，不猜测恢复顺序或声称已经回滚。
明确编辑本工作区控制文件时只放行其自身地址，其他控制
别名仍不能共用其写入目标；只观察而不写入的配置和选择不增加其他库依赖。
当前选择实际变化时才执行写入目标检查，同选择 no-op 和只读查询保持不写入。
控制目录内的目录和叶子别名同样按真实目标检查，不依赖已知工作区摘要或事务 ID，
不读取历史选择、事务清单或锁记录的内容。
权威库通过软链接引用的库外知识、需求产物和覆盖模板
仍属于权威资料的写入禁区，包括目录别名内的再次外跳及尚不存在的目标。
此项检查只读取目录与链接元数据，不读取无关文档内容、不扩大普通编辑快照，
也不据其他工作区的选择记录推断其外部需求归属。main 和共享工作区仍可按原规则
编辑权威资料的合法别名；无关的损坏链接或目录循环不阻塞独立本地工作。
需要检查归属的目录无法枚举或元数据读取失败时，准备、应用与恢复均停止，不能把
未知别名集合当作没有别名。修复访问条件后可以继续原事务；这不扩大普通编辑的内容快照。
别名目录扫描持有目录句柄，并核对地址、目录身份及扫描期间的命名空间元数据。
父目录枚举得到的子目录或链接身份随遍历保存；子项解析及目录打开时须继续匹配
该身份，不能在父子交接时接受临时空目录并重新建立基线。
声明的根链接、子项链接及其实际目标同样保存身份，重复到达与遍历结束时复验；不能仅因路径已经访问
就跳过已还原或已被替换的目标。
已存在地址在解析前后的正向文件身份也须一致，不能在解析时短暂换到其他目录后跳过原子树。
已打开目录的重复 ENOENT、inode 或类型替换均须停止，不能跳过子树。已发现子目录的
祖先变为普通文件时，`ENOTDIR` 也须停止，不能作为损坏链接忽略。目录无法打开时，
已知叶子通过可遍历父目录的句柄、条目类型和稳定命名空间确认，无需文件读取权限或
父目录枚举权限。缺失也可由持有的可遍历父目录句柄、原生条目缺失及稳定命名空间证明，
无需枚举仅可遍历的父目录；命名空间不稳定或无法取得句柄时不能仅凭 ENOENT 放行。
合法缺失祖先可递归确认，不靠增加重试。
`ELOOP` 或解析循环错误本身也不证明目录可以跳过；只有在持有的父目录命名空间内
核实链接类型、绑定及循环关系后才忽略稳定循环，临时循环链接替换须停止。
别名解析前后均检查路径可访问性，不能用后续的 `..` 折叠掉不可访问的祖先后继续写入。
配置与当前选择文件仍要求直接地址；导入/归拢的来源快照仍拒绝软链接。

1. 检查发起工作区、目标和范围，读取稳定快照。
   完整快照逐级绑定已枚举目录的身份，持有目录句柄读取条目，并在遍历结束复验
   已读命名空间。来源子目录被临时换成空目录时停止，不能退到模板或报告无差异；
   真实空目录仍有效。该检查不扩大普通编辑的明确目标快照，恢复仍不重新快照来源。
2. 默认范围为宪法与项目长期记忆；选定需求时包含该需求目录内关联产物。
   来源知识目录、文件及宪法 provenance 按来源文件系统身份识别等价名称；原始快照
   保留实际拼写用于过期检查，需求选择字符串不因此改写。首次 INIT 使用相同识别规则。
   角色识别遇到权限或 I/O 错误时停止，即使内容快照已成功也不能把未知身份当作非知识
   文件而静默漏导入；明确可判定的非等价名称仍按原规则排除。恢复只使用保存的字节。
   已知来源文件直接读取并复验身份，短暂缺失不能退到祖先目录后判为非等价。候选规范
   路径缺失或身份不一致时，逐级使用已知来源父目录的名称查找规则判断；只有能够证明名称非等价才
   排除。此时只接受原生目录属性提供的敏感规则，不再使用候选或独立目录条目探测；
   ENOENT、探测期间 inode 不同及首尾 inode 相同均不能证明名称稳定非等价。
   原生属性失败、不受支持或缺少所需 Unicode 规则时停止，不能回退到目录观察。
   明确非等价名称及有原生规则依据的合法缺失候选继续排除；普通地址比较的缺失路径规则不变。
3. 输出候选差异及来源清单。选定范围内实际有差异的来源超过一个时必须明确提示。
4. 相同文件跳过；新增文件保留原字节；不同版本由模型准备候选或明确跳过。
   不按时间选胜者，不合并任务勾选并集，不因来源缺文件删除目标。
5. 没有真实共同基线时按双向差异审查，不伪造三方合并历史。导入宪法的历史来源
   如存在则与原文一起保留；不得将导入说成本次从模板生成。
6. 应用时重新校验来源、目标和绑定未变，取得资料库写锁，写入恢复日志，逐文件
   发布并回读。冲突未解决不写入；失败保留恢复记录，恢复不得覆盖意外的新变更。
7. 报告实际纳入、跳过及未解决项，保留来源，不自动分发或删除副本。

候选与恢复信息保存在目标库的 `transactions/`，不归拢到其他库。普通模型文件
写入也通过候选流程；包内有写入行为的 shell helper 使用同一把锁。只读查询不加
写锁。操作完成后释放锁；中断后的日志可显式恢复，不把残留锁当作覆盖授权。INIT 或准备过程留下的锁可通过
`sdlc_store.py recover-lock --project <代码项目>` 检查并释放；仅记录的进程已退出时允许。
应用中断仍须对原事务执行 recover，归属不完整时停止并要求检查。
恢复逐项核实成功发布时记录的文件身份与修改时间，不能仅凭内容相同推断归属。
发布被拒绝的并发新文件会保留；发布后、归属记录落盘前发生中断，或旧事务缺少归属
证据时，保留无法确认的当前文件并停止。已经恢复到原字节的文件不重复写入。
逐文件发布不等于整个目录的原子切换，外部读者可能看到中间状态。

## 验证要求

使用合成 Git 仓库及真实 linked worktree 覆盖：本地优先、共享读写、main 独占归拢、
指定路径与子项目、损坏不回退、需求选择隔离、STATUS 无写入、默认导入范围、
多来源提示、来源/目标过期、冲突不落盘、重复无变化、恢复保护以及来源保留。
保持上游原始字节与独立 CLI 基线验证，并重新生成派生源码、dist 和 Marketplace。
工程通过不代表原生宿主或模型驱动业务验收。

每个快照最多 10000 个文件、总计 64 MiB，单文件最多 8 MiB；超限停止，不截断后继续写入。
普通编辑只对其目标及必要绑定应用此限制，无关的大文件不阻塞本次编辑。
