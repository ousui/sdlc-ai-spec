# Skill开发流程

普通工作按已授权的设计、实现、评测、审查和收口推进。设计批准来自用户，不能由测试通过推定。
本次SDLC v2完整设计和P0–FINAL持续工作已被明确批准，适用V2-WORK-PACKAGE.md覆盖。

实现前读取相关批准章节及当前代码，定稿共享协议；只把必要执行指导放进Skill。
通过真实命令表、参数、安装独立性和必要Agent前向案例验证；逐条记录失败责任层与修复。
行为验证以观察到的代码/日志/断言为准，样式和构建通过不能替代产品验证。

正式产品评测先保存需求、实际加载安装版Skill，再形成实现与验证，禁止先准备候选答案后补记录。
每逻辑工作包适用测试、diff检查、紧凑进度和本地commit；外部写入、发布和认证单独按当前授权。
