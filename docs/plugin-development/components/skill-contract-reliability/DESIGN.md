# Skill 输入契约与执行可靠性修复计划

日期：2026-09-08。状态：ready；按 Maintainer 本会话明确要求连续修订、实施和验证，不代表最终验收或发布批准。

## 1. 结论与范围

本次解决真实使用中的阻碍：Skill 随包契约遗漏关键输入限制，模型构造非法请求后，CTX 又把输入错误错误地投影为全部 Gate Check 失败，且 dry-run 丢失错误。不能将此归责为 approval-bot 产品缺陷，也不能只修正一次输入而不修复可重复发生的契约缺口。

范围限定为 CTX 及其他 Skill 的同类输入说明、输入整理、结构错误定位、元命令输入隔离问题。回归以测试用例、受控 Fixture 和 mock 为核心；必要时使用既有 test-sdlc。所有正常使用均为正式使用，不另设“首次调用实验”、模型实验或新宿主认证门槛。

不扩展工程采集器、技术栈适配、Store、部署、发布、通用 Schema 框架或跨阶段 wire 格式。不会为凑九个 Skill 的修改量而修改无同类缺陷的实现；不引入新的人工审批或业务 Gate。不修改 docs/v1.1 领域规范、用户现存项目、已冻结 Artifact 或安装缓存。

### 当前版本补丁边界（2026-09-08 追加决定）

本次仅修复当前版本的 bug，不进行版本迭代。Plugin / Skill 版本号、公共 Contract ID、输入输出 Schema、Store 格式及现有命令保持不变；不引入新必填字段、版本选择、数据迁移或 Schema 变更验证工作包。用户更新同一版本的插件文件后，旧合法请求和已有记录继续按原入口使用。

已有工程回归仍保留；它们不是本次新增的 Schema 迁移门禁。Source Lock 仅在其实际引用字节改变时按既有工具重算，不修改版本或让用户执行迁移。新增输入拒绝仅修正错误输入的既有处理，不借补丁扩大封闭字段集合。以旧合法请求、原记录只读检查及未完成流程续行为兼容性回归，不要求用户重新建项目或丢弃历史。

## 4. 输入整理：对人宽容，对事实和权限准确

用户自然语言与 Runtime 标准输入不是同一个层次。Skill 应结合上下文理解明显错字、单词拼写和中英文表达，例如“构建”、明确构建语境中的 bulid，不为这种格式问题中断用户流程。Agent 在正式提交前自行整理为已支持标准值；用户无需手填枚举、内部 ID、摘要或 Invocation。

程序端只允许字段限定、无歧义、可记录的归一化，例如标准枚举的大小写/首尾空白以及明确登记的工程用途别名。标准枚举集合本身不扩大；归一化产生 warning，保留字段路径和采用的标准值，不回显原始敏感文本。

禁止模糊修正 Authority/Revision/ID、摘要、命令、路径、资源范围、访问能力、Exception、确认及授权。source_worktree 不能仅凭词相似就认定为 repository；需要观察真实 Git/工程事实。depends_on 的文字依赖可由 Agent 根据已知组件唯一映射成 ID；无法唯一确定时保留缺口，不猜。普通拼写整理不授权重放已经发生效果的正式失败调用。

## 5. Runtime 最小修复

沿用当前 Builder/Validator/Store 分层。优先补齐当前程序约束的随包字段、枚举与示例；生成检查复用已有常量/数据结构，不建立第二套通用校验框架。

纯输入检查在分配和写入前完成。CTX 拒绝非法输入时返回 ok=false、status=failed、artifact=null、gate=pending；修订拒绝保留原 Revision 不变，明确本次请求未评估，不改历史 Gate。dry-run 返回相同错误类别、路径与约束，始终不生成 Authority。最终确认被明确拒绝时只标其对应 Check fail，不能抹为 pending 成功。

Evidence 的 sha256 是当前插件表示规则，不冒称 Core 强制所有证据使用该算法。提供会话证据的最小内容留存、来源定位和真实字节摘要方法；Supporting Member 与 Evidence 绑定的摘要需一致。摘要证明完整性，不证明身份或授权。不能用“不适用”或随机摘要填平缺口。

新 Git 观察记录完整 commit；dirty/untracked 内容另外绑定观察范围和字节摘要。表示合法、对象可解析、内容一致性是不同结论，不把看似合法的 hash 当作已核验事实。保持既有泛 VCS 输入兼容；不强制联网、全仓扫描或改变冻结历史解释。

## 6. 随包说明与同类核对

共享 Skill 输入整理规则描述用户意图处理；各 Skill 私有契约描述标准字段。对 CTX/REQ 的现有字段/枚举生成可核对说明；DSN/PLN/IMP/VFY 补当前必要的嵌套映射。RLS/Status/GitHub 复用其已有 Contract/Schema。独立测试 Oracle 来自真实缺陷和领域规则，不从生成器自动生成全部 Expected。

未知字段沿用现有已声明边界，不趁此次收紧全部旧请求。缺失事实、确认不存在、N/A、非法输入分别处理；不能为通过结构检查伪造 ready。授权、只读、Supporting Member、prepare_confirmation、CAS 和写前当前性检查继续保留。
