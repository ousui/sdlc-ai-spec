## 3. P1：早期代码审计与契约定稿

> **速读：已有五项基础测试不证明内核正确。先审核现有32表实现与批准设计的差异，补上会影响六阶段稳定性的最小规则。**

先运行已存在的 v2 基础测试，记录真实命令、数量、退出码和准确 HEAD。以批准设计检查早期代码，而不是为了让早期代码通过而修改设计目标。

优先审计：

| 检查面 | 必须明确的行为 |
|---|---|
| 嵌套输入 | 未知字段、类型、枚举、缺字段和批次内引用在生产端明确报路径；对象身份由程序分配 |
| 作用域 | 项目/需求/Revision/任务/结果的跨表关系不能串到其他作用域 |
| 快照 | 已提交内容和附件关系不可改写；创建子快照顺序符合外键/事务规则 |
| 依赖 | 来源/覆盖与执行依赖分离；检查开始/执行/完成时点；联合依赖图无环 |
| 执行事实 | Step 完成不等于检查 pass；AI 自述不等于命令执行证据 |
| 幂等 | 同键同请求回同结果；同键异请求冲突；unknown 副作用先回查 |
| 审批与身份 | auto 使用真实授权边界，不靠将 actor 改为 human 绕过检查 |
| 查询与恢复 | 只读查询不写业务状态；打开数据库前失败也有诊断；操作成功而视图生成失败不能重做业务副作用 |
| 并发与文件 | 短事务、锁生命周期、原子写文件、故障后可恢复；有界日志和安全路径 |
| 可移植性 | 资源键、相对附件键、语言无关 JSON/错误语义；不把绝对路径作为业务身份 |

冻结首版命令与结果契约。命令名可以按批准设计细化，所有 Skill 及生产/消费验证共享同一实现。32表是已批准模型基础，不以表数作为质量指标；必要修正要给出理由、最小 DDL 差异、测试与规范同步，不扩成通用数据库平台。

把旧 docs 的当前规范迁到 `docs/spec/`，标识 `spec_version=2.0-draft`、`api_version=2`、初始 `schema_version=1`。规范解释领域语义，随插件打包的契约控制 Runtime。设计模型检查的28项结果只是设计证据。

**完成证据**：差异审计、契约样例/负例、旧依赖缺陷的新最小回归、可读的本地检查点 commit。

## 10. 本地进度、证据与持续执行方式

> **速读：一个进度文件＋本地 commit＋非 VCS 的证据目录即可。无需依赖远端，换会话先读进度而不是从头规划。**

使用一个持久工作包目录。规范仓库唯一进度文件建议 `docs/work-items/sdlc-v2/PROGRESS.md`；实验室只保存场景定义、测试代码和紧凑证据索引，运行大文件保存在用户已有归档目录，或 `test-sdlc/.local-runs/sdlc-v2/` 并在该目录单独放 `*` 忽略规则。

两个 Git 仓库的源码/规范/测试/进度允许提交；业务 `.sdlc` 和运行数据默认不入 VCS。测试产品实际代码仍在普通产品工作副本，记录其 commit 或文件摘要；不上传生产资料、真实账户或凭据。

每个逻辑工作包、每个关键缺陷修复、每个已完成轮次后：运行相关检查 → `git diff --check` → 仅暂存本任务文件 → 本地 commit → 更新 PROGRESS 的实际 SHA、已完成/未完成、关键证据位置、唯一下一动作。先保留记录再进行下一包；不在每次工具调用后提交。

建议证据目录：

```text
<evidence-root>/
  environment.json
  round-0/<project>/<attempt-id>/
  round-1/<project>/<attempt-id>/
  round-2/<project>/<attempt-id>/
  final/<runtime-sha>/
```

每次执行保存 manifest、原始需求、实际 Skill 调用/工具轨迹、`.sdlc` 恢复包、产品差异、测试 XML/JSON 或原始日志，以及交付回读。manifest 至少含 runtime_sha、lab_sha、installed_tree_digest、product_input、product_output、host/model/reasoning、scenario_id、执行类型、准确命令/退出码、干预/异常计数、文件摘要。

多 Agent 可用于独立评审和不同产品副本，存储/Schema/契约保持单写者；不并行修改同一 worktree 的主线。没有独立 Agent 时按自审记录，不制造审阅人身份。

宿主中断或上下文不足时，保存可恢复状态、当前正在运行的命令/进程、已知副作用和唯一下一步。新会话读取 PROGRESS、实际 git 状态和最近结果后接续。正常阶段完成不是停机理由；真实权限/工具不可用只阻塞相应动作，不伪造通过。
