## 2. v1.0 / v1.1 版本边界

### 2.1 v1.0 保持不变

- `docs/v1.0/` 保持字节不可变，并继续由现有 `SHA256SUMS` 验证；
- v1.1 是新的完整 Spec Snapshot，不是对 v1.0 的原地修改；
- v1.0 Frozen Artifact 始终按其准确 `Evaluation Contract Set` 解释；
- 本计划不设计 v1.0 自动迁移工具。

### 2.2 v1.1 唯一语义变化

v1.1 解除 `artifacts/**`、`revision-index.md`、`revisions/<NNNNNN>/`、主文件路径和目录扫描对 Canonical Artifact Authority 的绑定，改由逻辑 Artifact Store Contract 以完整 Canonical Revision Payload 表达 Revision Snapshot。Payload 是 Store 层逻辑存储单元，不是新的 Artifact 字段、Reference 类型、Status、Gate、数据库表或领域 Artifact，并包含：

- 主要 Canonical Markdown/YAML Blob（primary Canonical Blob）的完整原始字节（raw bytes）；
- 当前 Revision 本地拥有的全部 Member（all locally owned Members）原始字节；
- 每个本地 Member 的既有稳定身份（stable Member identity）、Canonical Member Name 或等价稳定名称、Media Type 与 SHA-256；
- 能够唯一闭合实际本地 Member 集合的现有 Canonical Manifest 内容，即 Manifest-Member closure。

Artifact Store Contract 继续表达：

- Artifact 与 Revision 分配；
- 完整 Canonical Revision Payload 读写；
- Revision 状态转换；
- 准确 Reference 解析；
- digest 验证；
- 失败关闭。

上述 Store 表达不得新增 Member 类型、Manifest 字段或 Reference 语法。

Core、CTX、DSN、IMP 只移除上述物理目录耦合，不改变其业务语义。其他 Phase 和 Domain Spec 只进行必要的 Snapshot 版本与引用更新。

本地拥有的 Member 包括 DSN Artifact Set 的 Domain Member、由当前 Store 保存的 Supporting Member，以及其他由现有 Phase / Domain Contract 定义并由当前 Revision 本地拥有的成员。Supporting Artifact 的外部不可变 Reference 继续保持既有准确 Reference、摘要和访问边界，不要求复制为本地 Member，也不得被静默删除。

### 2.3 必须保持的领域 Contract

以下内容保持不变：

- `sdlc-ai-spec/artifact/v1`；
- `sdlc-ai-spec/project-context/v1`；
- `sdlc-ai-spec/final-confirmation-authority/v1`；
- Artifact ID、CTX ID、Revision、Base Revision 与项目范围唯一性；
- `open / frozen / abandoned` Revision State；
- `draft / waiting_input / failed / ready / ready_with_exception` Artifact Status；
- Context、Artifact、Item、Member、Spec、Authority 与 VCS Reference 的现有字段、用途和语法；
- Evidence、Exception、Open Item、Disposition、Check、Gate、Final Confirmation 与责任边界；
- Frozen Revision 不可修改；
- 不使用 `latest/current` fallback；
- 完整 Canonical Markdown/YAML Blob 与 Canonical Blob SHA-256。

三个 `/v1` Contract ID 的兼容判断，以完整保留主要 Canonical Blob、全部本地 Member、稳定 Member 身份、原始字节、SHA-256 及 Manifest-Member closure 语义为前提；任一闭包语义无法保留时不得宣称 Contract 兼容。

发现必须改变任一上述内容时停止 v1.1 编制，不得以存储修正为由静默改变领域 Contract。

## 3. 唯一新增正式 Spec

v1.1 只新增一份正式 Spec：

```text
artifact-store-spec.md
```

该 Spec 位于 Core 之后、Project Context 或当前 Phase Spec 之前，进入全部 v1.1 Canonical Artifact 的 `Evaluation Contract Set`。它只定义以下最小逻辑操作：

- `initialize`；
- `allocate artifact`；
- `allocate revision`；
- `read revision`；
- `write open revision`；
- `freeze revision`；
- `abandon revision`；
- `resolve exact reference`；
- `verify digest`。

它还必须定义：

- 一个项目只有一个 Canonical Store；
- 同一 Artifact 同时最多一个 `open` Revision；
- Revision 单调增加且不复用；
- Frozen Revision 不可修改；
- 写操作具有原子事务边界；
- 准确 Reference 只解析指定 Revision；
- Store 不可用、损坏或事务失败时 fail closed；
- 不静默降级到文件或临时目录。

`artifact-store-spec.md` 必须定义完整 Canonical Revision Payload，并明确以下现有操作对 Manifest-Member closure 生效：

- `read revision` 读取并验证主要 Canonical Blob、全部本地 Member、Manifest 闭包和每份原始字节 SHA-256；成员缺失、未登记、Member ID 重复、摘要不匹配或无法唯一闭合时失败；
- `write open revision` 在一个 transaction 中一致写入主要 Blob、本地 Member、Member 元数据和 Manifest 闭包，不允许部分成功；
- `freeze revision` 只在主要 Blob 和全部本地 Member 均已持久化、读回且摘要通过，Manifest 与本地 Member 集合完全一致，并满足既有 Gate 与 Final Confirmation 后执行；冻结后主要 Blob、全部本地 Member、成员集合、稳定身份与摘要均不可修改，任何变化进入新的最大 `open` Revision；
- `verify digest` 同时验证 Canonical Blob SHA-256、每个本地 Member SHA-256 和 Manifest 与实际成员集合完全一致，不得只验证主要 Blob 后报告整个 Revision 完整。

该 Spec 不定义 SQLite 表、列、索引、PRAGMA、WAL、Migration、固定数据库路径、配置文件或实现代码。当前 Plugin 使用 Local SQLite 的决定只登记在 `docs/plugin-development/DEVELOPMENT.md` 和架构文档中。

Human Review View 保持为 Plugin Projection。其文件格式、映射 Schema 和编辑器适配留到 Skill 实现阶段，不新增独立 Projection Spec。

## 5. Core、CTX、DSN 与 IMP 的精确边界

### 5.1 Core

- 用逻辑 Artifact、Revision、Canonical Blob 与 Store 操作替换固定目录布局；
- Revision Snapshot 的 Store 表达必须包含主要 Canonical Blob 和当前 Revision 本地拥有的全部 Member，并通过既有稳定身份、原始字节 SHA-256 与 Canonical Manifest 唯一闭合；
- 将准确 Resolve 改为 `resolve exact reference`；
- 将分配、写入、Freeze 与 Abandon 改为事务语义；
- 在 v1.1 `Evaluation Contract Set` 中加入准确 Artifact Store Spec 引用；
- 保持全部领域字段、Reference、Gate、Final Confirmation 和摘要规则不变。

### 5.2 CTX

- 用 Store 中唯一 CTX Lineage 替换 `artifacts/000-ctx/` 物理布局；
- 保持 Context Reference 为准确 `<CTX-ID>@<Revision>`；
- 保持 Project Boundary、Basis、Item、Status、Gate 与刷新规则不变。

### 5.3 DSN

- 用同一 Revision 的主要 Canonical Blob、全部 Domain Member 与本地 Supporting Member 的原始字节、稳定身份、Media Type、SHA-256 和现有 Manifest 闭包表达 DSN Artifact Set；
- 保持 16 份 Domain Spec、固定 Domain Member Name、`DOM-*`、`SUP-*` 和父 Gate；
- Supporting Artifact 的外部不可变 Reference 继续保留准确 Reference、摘要和访问边界，不要求复制进 SQLite；
- 不把每个 Design Decision 或 Domain 内容规范化为关系表。

### 5.4 IMP

- Claim 成功后通过 `allocate artifact`、`allocate revision`、`write open revision` 和读回验证物化 IMP Artifact；
- 物化或校验失败时只使用 `abandon revision` 终结已预留 Revision；
- 完整分配、写入和读回前不得修改产品；
- Claim Authority 与 Artifact Store Authority 的既有先后和失败关闭边界不变。
