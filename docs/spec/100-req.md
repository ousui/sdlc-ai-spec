# REQ

change.create先保存原始文本、交付目标、范围和真实本地授权，分配change/revision/source身份。
phase.submit批量保存需求/验收及来源关系；update_revision_text在同一个REQ草稿事务修订需求级标题、摘要、目标、范围和范围外说明。
省略字段保持；不写身份、状态或权限。generation、输入/关系校验、字段更新和回执共同保证原子提交与幂等。
phase.complete检查覆盖并冻结，创建DSN草稿；下游继承修订后的完整内容。原冻结快照不可原地改写。
复杂含糊语义由当前Agent澄清；Runtime字段校验不能代替业务判断。
Agent识别冲突后run.request_input记录question/conflict/当前revision及field_path并返回needs_input。
待答事项通过run.get、phase.prepare和status可读；原来源、generation和权限不变。
run.answer_input记录实际回答及其依据，绑定原问题；不会按自然语言或JSON路径自动改写内容。
明确指向五个需求级文本字段的问题，回答后仍有待应用义务；Agent在REQ同批回写对应字段和受影响明细，提交回执保存回答与内容版本的应用关联。
未应用不能完成后续阶段；该义务随内容祖先及复制/导入保留，不取决于当前Run是否更换。通用问题不默认指向goal。
原始输入可保留历史待定描述，当前有效范围应与需求及验收一致；语义一致性由Agent复核，不设“等待明确”等字符串黑名单。
该操作不新增授权、不签human审阅；新Run或取消再重开也不能自动消除未回答的问题。
