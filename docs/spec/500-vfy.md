# VFY

check.run 的结果来自真实工具。check.record_review 只允许非 test 的 Agent 方法，
保存 actor 和 self_review 性质；不能向命令 Check 写入模型声明的 pass。
任务执行完成和检查结果分别保存，原始失败与后续通过都不可覆写。

Check 的 input_paths 是读依赖闭包，与 Task 的写入 scope_paths 分开。未声明时覆盖完整 main 产品输入；
显式缩小范围时，Agent 必须包含源文件、断言和实际依赖，共享构建描述仍自动计入。
支持资源键，不能以 tests/** 的写权限推断只依赖 tests/**。
结果复用同时要求当前定义、来源/需求/验收语义、Context、相关任务关系、代码字节、环境和时效适用。
HEAD 仅记录来源，不单独作为全链拒绝依据。Python 路径和虚拟环境依赖实际字节参与摘要；
不能完整观察的符号链接依赖明确阻断。

finding 按检查、验收、类型、回流阶段和问题身份去重；Agent 可给稳定 issue_key。
不同缺口分别保留，同一缺口从 advisory 升为 blocking 不可被旧级别掩盖。
addressed 只表示已处理；resolve 必须引用同一目标之后实际产生且当前适用的 pass 结果。

check.evaluate 从必要检查、任务、blocking finding、当前绑定工作区的本地未知操作计算 converged。
phase.complete VFY 需执行租约；无缺口才返回 RLS。产品缺口回流到最早相关阶段，
已知失败不被尚未完成的验证任务或依赖审阅阻止退修；原完成条件和依赖不变，
当前Run未完成的任务尝试保留为interrupted/unknown，恢复后重新开始任务。
仅有缺少检查或未完成任务时仍返回VERIFICATION_PENDING，不消耗修复轮次。
未知/环境不足保留现场，不耗用产品修复预算。默认格式修复3次、修复5轮、连续2轮无进展暂停，
预算持久化，可用 run.configure 根据明确要求预先设置或在检查后增加；auto 不自行增加预算。
格式失败保留原始字段路径，不分配半个内容批次。重新取得租约不重置预算。

check.reuse 显式保存 reused_from_id，沿用原观察时间和有效期；不伪装新的工具执行。
