# AI 与人工协作建议

> 本文件是非强制使用建议，不是 Artifact 合规条件。是否使用 AI 不影响 Spec 对结果的判断。

## 1. 基本边界

| 原则 | 说明 |
|---|---|
| AI 是提效手段 | 可用于分析、编写、检查和执行，也可以不用 |
| 产物标准相同 | 人工与 AI 生成的内容使用同一模板、Evidence 和 Gate |
| 不使用固定比例 | 不用 AI 参与比例、调用次数或代码占比评价是否合规 |
| 不转移责任 | 业务目标、主观判断、外部授权和风险接受仍由有责任的人工或外部权威承担；仅客观 Artifact 合规确认可按 Core 委托独立 Reviewer |
| 高风险需明确确认 | 安全、权限、隐私、资金、合规和不可逆变更不能由模型自行批准 |

## 2. 各 Phase 的适合用法

| Phase | AI 适合辅助的工作 | 需要人工负责的事项 |
|---|---|---|
| REQ | 归纳输入、识别缺口、整理目标和验收条件 | 确认真实业务意图、范围和优先取舍 |
| DSN | 探索现状、比较方案、检查 Domain 覆盖和矛盾 | 确认关键取舍、风险接受和未确定边界 |
| PLN | 拆分 Work Item、检查覆盖、依赖和范围冲突 | 确认计划是否符合实际交付约束 |
| IMP | 按确认的 Binding、设计和计划实施并执行局部检查 | 处理上游缺失决策和高风险偏差 |
| VFY | 设计与执行验证方法、汇总 Evidence、检查追踪覆盖 | 确认预期用途和关键业务结果 |
| RLS | 绑定发版范围与结果、整理 Release Item 与 Post-release Confirmation Evidence、聚合发版结论 | 提供受限权限、确认目标侧事实并接受未关闭风险 |

## 3. 使用方式

- 为常见 Phase 提供固定模板、提示和检查入口，降低首次使用难度；
- 让 AI 依据明确输入生成标准 Artifact，不让模型自行发明结构和状态；
- 对不确定事实使用 Open Item，不用流畅文字掩盖输入缺失；
- 对实现和验证结果保留可复核 Evidence，不接受仅有结论的“已完成”；
- 发现 Requirement、Design 或 Plan 缺失时返回对应 Phase，不在下游静默补决策。

## 4. 结论

AI 的价值是提高各 Phase 形成合格产物的效率，而不是成为流程成立的前提。Spec 只规定结果必须满足什么，不规定由谁以何种工具完成。
