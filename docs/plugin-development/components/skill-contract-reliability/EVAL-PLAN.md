# Skill 输入契约可靠性评测与复现计划

日期：2026-09-08。阶段：design。状态：draft。本文定义未来执行方式和 Expected，不是 EVAL-RESULTS，不声称计划中的案例已执行。

设计与问题 ID 见 [DESIGN.md](DESIGN.md)。固定当前反例基线 `aed8eb69d2b74ec27bdcb2fb356cb02b68602289`；修复完成后再登记新的准确提交。两份源码分别隔离执行，不将旧结果改成新版本结果。

## 1. 三种证据分别验证什么

| 路径 | 输入从哪里来 | 证明什么 | 不能证明什么 |
|---|---|---|---|
| A：协议与语义反例 | 固定 JSON/字节、真实失误的脱敏重建 | Validator、状态、错误和副作用边界 | 模型会不会构造这些输入 |
| B：正式项目链 | 固定业务场景、项目基线、正式 CLI | 业务变化及 CTX→RLS 衔接、当前源码和环境 | 原生 Skill 发现、任意模型、任意项目或生产发布 |
| C：文档可用性实验 | 新上下文仅给安装包文档、原始诉求和受控项目事实 | 模型不读实现/测试答案能否生成正确请求 | 全平台原生认证或任意模型成功率保证 |

独立语义判断来自固定 Spec/业务验收与原始缺陷，不从待测代码生成 Expected。流程测试里的 synthetic authority/PassingVerifier 仅能标记其测试边界，不能混入真实项目正式 Authority 证明；后者使用其正式 CLI 与真实复核记录。

## 2. 在其他项目复现的具体步骤

1. 锁定 Plugin SHA/tree、安装包摘要、真实运行路径、解释器、宿主/模型设置；确认没有用缓存中的另一个版本。项目锁定 commit、选中子目录、dirty 范围及文件摘要。历史数据读回，不重新指定 Ref 去迎合记录。
2. 从源项目准确对象创建一次性副本，业务项目和用户 .sdlc 均不直接改动。干净基线与 dirty 派生用例分开；绝不对用户 worktree reset 或清理。回归产物写入仓库外，临时目录保留到诊断结束后按名单清理并报告。
3. 提取或重建一份最小合法 CTX 输入，给资源、证据和业务缺口正确来源；首先证明它无结构错误，允许因真实缺少最终确认而 pending，不能为了基准成功伪造 ready。
4. 每次只注入一种错误：source_worktree、中文用途、非法环境、说明文字 depends_on、会话摘要“不适用”、时间作为基线、未知字段。保留未变字段，分别检查预检、Builder、dry-run 和正式拒绝路径的结果与实际写入。
5. 在至少两种不同技术栈的项目副本重放相同逻辑错误。预期错误路径、类别和副作用相同；项目特有事实不要求完全相同。这样能证明错误属于公共协议而非语言。
6. 使用修复版本重放同一反例。正确结果是准确拒绝或等待，不是让非法数据通过。再运行合法配对输入，证明没有为了拒绝错误而阻断正常流程。
7. 使用新的执行上下文，隐藏测试输入、脚本答案和 Runtime 实现，只开放 SKILL.md、其随包文档/Schema/示例、正式工具入口及该项目事实。给自然语言需求，观察第一份请求，而非把回归脚本 JSON 直接塞给模型。
8. 对首轮失败记录原因：文档未定义、文档冲突、模型未遵守明确约束、采集错误、环境能力不足、Runtime 缺陷或真实业务缺口。保留修正前后请求；真实业务决定需要用户输入时属于正确等待，不计作格式失败。
9. 所有证据绑定输入摘要、实际命令、退出码、结果、Store/Claim/产品/目标前后状态；清理只针对已登记临时副本。错误消息与导出材料先脱敏，不能把 Secret 或原始授权凭证写入仓库。

第 3–6 步是确定性测试，可使用 Fixture；第 7 步不得复用该 Fixture 作为模型答案。模型产物可被正式 Runtime 执行，但“模型不读实现”是本项评测条件，不改变生产 Runtime 使用代码和依赖的权限。

实施者先将每个大 Case 展开为必要子用例并登记唯一测试 ID；不把每个语言组合复制一套相同测试。Expected 在修复前固定，确认真错误后才能更正规范误判，修改原因独立留痕。

## 5. 有限的模型与文档实验

默认建议 3 个短路径 × 2 个用户可用且明确选择的模型配置 × 2 次新上下文，共 12 个执行单元。不是 12 次七阶段全链，也不需要新增付费订阅；模型不可用时如实缩小覆盖并列出未执行配置。实际型号、推理级别、最大费用与宿主须在 evaluate 前记录；本设计不擅自更改当前模型设置。

三个路径：approval-bot 的 CTX 采集；Minimal Admin 的 REQ；已冻结完整范围下 Fansite 的 DSN/PLN 输入适配（每个 Skill 分开显式调用，授权不传递）。SpringGear/JDK 工程差异在能力测试和固定业务链覆盖。可以根据首个证据选择更有区分度的项目替换，但先固定选择依据，不看结果后挑最容易的输入。

每单元建议上限 15 分钟、2 次写前结构纠错；出现未知效果、缺必要权限或真实业务决定立即停止。纠错次数和首轮失败必须保留；额度耗尽标 blocked，不算失败重跑抹除。12/12 也只代表该样本，不能推导“任何模型都不会出错”。

记录：首份请求合法率、仅靠文档解决率、查看实现/人工给 JSON 的次数、真实业务询问与无谓格式询问分别计数、最终错误分类、令牌/时间/重试成本。schema/权限/证据安全类异常容忍为 0；可解释的真实业务等待不要求强制 ready。

本工作包建议必须观察本次缺陷相关短路径，但不恢复所有宿主原生独立认证门禁。without-skill 对照和扩大样本仅在结果难解释时另行选择，默认不追加。模型文本内容可不同，比较事实、范围、合法状态和可追踪性，不按自然语言逐字相等打分。

## 6. 去重后的验证顺序与触发条件

1. 日常修改：执行受影响的固定反例与配对正例，外加结构/生成检查。小改不自动重复全仓或全项目链。
2. 变更集稳定：在干净准确提交选一次 full/strict/e2e 最高所需入口；本轮涉及多阶段契约，最终建议一次 e2e，不预先再跑相同 full+strict。
3. e2e 中已有 SpringGear/Gin-Vue-Admin 固定 Sandbox 链继续作为 Runtime 集成；用户三条业务链从 test-sdlc 复用，避免多个包装器各自又执行全仓单测。若两条 SpringGear 覆盖完全相同，先建立断言映射再合并；只因项目同名不能删除。
4. 文档实验独立记录为 C 类，不用三条 scripted replay 代替，也不将手动原生反馈伪装为自动认证。
5. 新上下文复核聚焦协议漂移、错误聚合、兼容和删除后的风险覆盖，读取已有准确证据，不无条件重新跑所有测试。

同一最终批次 key 包含源码 SHA、Case ID、输入/项目快照摘要、解释器/沙箱配置、Contract Set；只对完全同 Subject 去重。源码或测试 Oracle 变化后旧结果不能直接复用。模型实验 key 还含模型/推理/提示词/上下文版本，不能用两个不同配置冒充重复试验。

## 7. 记录、归档与停止条件

报告最少包含：准确源码/测试源码、实际 Runtime 路径和包摘要、项目来源与完整基线、宿主/工具版本、Case 与输入摘要、首轮及每次重试、实际命令与退出码、错误字段、Artifact/Revision/Claim 状态、真实业务断言结果、Store/源文件/目标副作用检查、未验证项。

报告目录写在检出树外；源码只保留长期测试定义、固定脱敏 Fixture、设计与紧凑索引。历史原始失败和报告不可覆盖，脱敏不能破坏测试 ID/必要证明字段，冲突时失败关闭而非猜测补全。

完成条件：已登记确定性反例和正例全部符合 Expected，三项目原业务义务不缩水，独立文档短路径在约定预算内给出准确结果，权限/只读/零未知效果证明完整，删并映射无风险孤儿，旧合法请求与 frozen 边界正确。任何未执行项、环境不足、待确认业务或不支持技术栈单列，不合并成全局 PASS。

执行本计划需要后续 implement/evaluate 工作包。当前只完成设计与列明在 DESIGN 中的最小诊断，不生产新的业务闭环证明。
