# SDLC 资料梳理与修订

`sdlc-refine` 用于把已有资料整理为准确、一致、可追溯且便于继续工作的内容。
它支持规范整理、内容校正、依据核对、补全已确认信息、结构重梳，以及版本适配和中断恢复。
普通整理不要求发生插件升级，也不要求所有阶段产物齐全。

这是安装包中的独立辅助 Skill，不加入九项上游阶段或阶段状态。
仓库维护 Skill `sdlc-maintain-upgrade` 负责锁定上游源码；本 Skill 面向业务项目已有资料，不负责安装插件或升级仓库源码。

## 使用方式与范围

可以要求“整理当前需求中不规范的内容”“依据已确认决定修正 spec 与 plan 的冲突”
“重新梳理这些任务的叙述、分组与依赖”“评估旧需求能否用当前插件继续”或“恢复更新时中断的 CONV”。
按用户指定的文件、需求或项目范围处理；不会由一个文件的问题自动扩展到全库。

| 请求 | 行为 |
| --- | --- |
| 查看、评估、讨论如何整理 | 只读分析，在会话给出问题与方案 |
| 整理、修正、重梳、执行适配 | 在已有授权范围内准备候选、应用并复核 |
| 涉及尚未决定的业务冲突 | 先完成独立部分，再提出具体待决项 |

已有授权与明确决定继续适用，不逐文件重复询问。不规范的判断依据项目约定、具体错误和使用障碍；
新模板的风格不是旧文档必须重写的理由。用户明确要求统一格式时可以整理呈现，同时保留机器契约与业务含义。

## 内容修订

标准维护在 [内容修订标准](../src/skills/sdlc-refine/references/revision.md)，随 Skill 分发。
有明确依据时修正错误、引用和相互矛盾的表述；缺少事实时保留未知，不为凑齐模板编造需求或证据。
代码用于观察实现现状，不自动成为修改原始业务要求的依据。

重梳必须保留目标、功能、约束、验收、任务、依赖、排除项与未决问题的去向。
稳定编号尽量保留；必要修复建立映射并同步引用。既有完成声明、勾选和人工评审责任与文本修订分开处理，
只落实已有明确更正决定，不由整理操作自行宣布阶段完成。

明确废弃的正文与文件退出当前活动输入：段落通过全文替换移除，整份普通文档使用
`{"action":"delete"}` 实际删除，与活动引用修订、合并目标一起准备和应用。空文件或废弃占位文档不算删除完成。
恢复依据保存在独立的事务快照中；后续流程不得据此重新补回已经废弃的工作。

任务编号移除后，事务在需求目录维护 `.task-ids.json`，只保存 schema 和已用编号上界。
它与任务变更同一事务应用、核验和恢复，即使整个 `tasks.md` 删除也保留。该记录不是任务或业务正文，不参与 IMPL 执行。
TASK、CONV 和 REFINE 分配新编号前调用包内只读 `task_ids.py --project … --feature …`，
计入活动编号和历史上界，从返回的 `next_id` 继续；CONV 用 `high_water` 作为 `M`。
删除 `T050` 后，新任务从 `T051` 或更高编号继续；试图复用退役编号会被事务拒绝。
保留有效义务的原编号，尚无编号移除的新需求不会产生历史记录。该规则是明确的本地编号续接适配，
不改上游原始正文、阶段顺序、业务判断、确认或发布授权。

## 版本适配与调用恢复

具体规则见 [兼容与恢复标准](../src/skills/sdlc-refine/references/compatibility.md)。
插件版本、初始化历史版本不同或旧缓存被清理，本身不构成不兼容。

| 结论 | 处置 |
| --- | --- |
| `compatible` | 保留材料字节，满足恢复条件时续办原请求，无需重复调用 |
| `adaptation_required` | 准备具体转换，按授权用现有事务应用并复核 |
| `blocked` | 指明具体缺件、冲突或未知副作用及解除条件，只暂停受影响部分 |

一次调用使用一个完整包。旧包失效时从宿主当前清单、安装记录或明确路径重新定位；
完整重载、核对兼容性和已有操作结果后继续，避免覆盖文档或重复追加任务。
旧包已清理时可判断当前入口是否适用，但不能声称完成了两个发行包整体等价比较。

## 写入与完成边界

修订复用 `store_changes.py` 的候选、快照、写锁、应用和恢复；只读分析或没有实质差异时不准备事务。
应用前复核输入与授权，应用后回读并检查原始义务和引用。资料搬迁、控制 schema 或事务格式没有可靠适配器时，停在具体方案。
不会为了整理刷新初始化历史、生成 provenance 或批量勾选任务。
删除只面向普通文档，不用于控制文件或末级软链接；导入/归拢仍不因来源缺失自动删除目标。
删除及编号历史事务使用 schema 2，旧包不能应用或恢复它们。恢复核验删除回执和当前状态，
仅当目标不存在时还原，并保留原权限；人工重建或归属证据缺失时停止，保留现状供核对。

STATUS、XCHK、HUMA、CONV 的原有职责不变，它们的调用不自动授予全面改写权限。
真正拆成多个交付需求时使用 CUT；代码实施和阶段验证由适用流程处理。
单独调用 REFINE 不自动串联其他阶段，恢复已授权的原调用按恢复规则处理。

工程验证覆盖打包、引用和现有解析/事务契约；实际 Agent 的修订质量、客户端更新恢复和真实项目验收需要独立验证。
